## 提醒模式改造：加右下角提醒队列
- 问题根因：`ReminderWorker` 逐条 `await publisher.PublishAsync`，而发布器内部 `ShowDialog` 阻塞到用户处理 → 多条到期提醒串行卡住整轮轮询。
- 新结构（3 个文件改动 + 2 个新文件）：
  - `Services/ReminderNotificationQueue.cs`（新）：FIFO 队列，最多同时可见 3 张卡，新卡在最底部、旧卡上移让位；间距 12、边距 24；单卡高度上限 `(工作区高-2*24-2*12)/3` 保证 3 张必放下；按 Reminder.Id 去重；`+N 条待查看` 角标；`Dispose` 关闭全部卡片。
  - `Services/ReminderResolutionHandler.cs`（新）：把用户选择落地为 MarkSelectedCompletedAsync / SnoozeAsync / 仅刷新。
  - `Services/InAppReminderNotificationPublisher.cs`：改为只入队并立即返回。
  - `Views/Reminders/ReminderNotificationWindow.xaml(.cs)`：非模态 `Show`、`Topmost`、`ShowActivated=False`、点 X 等价「知道了」；内容区改 ScrollViewer（长描述滚动而非裁掉按钮）。
  - `Services/TodoFeatureCoordinator.cs`：装配队列 + `StopAsync` 中 Dispose。
- 踩坑：`SizeToContent="Height"` 窗口在 `Loaded` 时高度尚未最终确定（实测 272 vs 实际 348），必须订阅 `SizeChanged`/`ContentRendered` 重排，否则卡片压出工作区。
- 已知取舍：入队即 `MarkDeliveredAsync`；应用重启后仍在内存队列里的提醒不会重发（要修需持久化「已投递未处理」状态）。
- 验证：临时 WPF 冒烟程序（5 条、高度不等）实测 bottom=995=1019-24、间距 12、无重叠，关顶部卡后补位且 pending 2→1；测试套件无新增失败（Native oracle 为既有失败，Message feed 那条是 flaky）。
