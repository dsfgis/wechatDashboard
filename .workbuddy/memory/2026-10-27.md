## 待办跨群去重与多来源消息（已实现）

### 需求与已确认口径
- 同一件事在两个群被不同人提醒时，不重复建待办，两条消息都进入"原始消息"框。
- 判定口径：由 Agent 语义判定（模型调用），非标题匹配。
- 提醒时间只向后取更晚，更早的忽略；已完成/已忽略的待办不参与去重。

### 实现
- 迁移 v6 `todo-source-messages`：新表 `todo_source_messages(todo_id, message_id, linked_at, is_primary)`，回填历史 `todo_items.source_message_id`；建表语句同时加入 `SchemaSql`（新库）。
- 仓储：`GetByAnySourceMessageIdAsync`、`GetSourceMessagesForTodosAsync`（主来源在前，未写关联表时回退主来源消息）；`GetBySourceMessageIdsAsync` 改为先查关联表再回退主来源（第二条消息也能显示"已转待办"）。
- 合并逻辑：`SqliteTodoMerge.ApplyAsync`（关联消息 + 更晚提醒才改期并保留 Cancelled 历史 + 更晚截止时间才更新 + 刷新 updated_at），两个工作单元共用。
- 协议：`ITodoUnitOfWork.MergeIntoExistingAsync(MergeTodoRequest)`；`MessageProcessingArtifacts` 增 `MergeIntoTodoId/MergeDueAt`，`MessageProcessingWriteResult` 增 `MergedIntoTodoId`；`CreateTodoOutcome.MergedIntoExisting`。
- Agent：`IMessageActionModel.MatchDuplicateTodoAsync`（OpenAI 兼容实现，返回 id 必须落在候选集合内）；`TodoDuplicateDetector` 只把最多 30 条活动待办送模型，异常/取消回退为"未命中"。
- 管线：`MessageCapturePipeline` 新增 `detectDuplicateAsync` 委托，事务前判定；命中时照常构造草稿，合并失败仍可新建。
- 手动链路：`MessageFeedViewModel` 用 `GetByAnySourceMessageIdAsync` 幂等，命中后合并并提示"已把本条消息加入原始消息"。
- UI：列表卡片多来源角标 `SourceMessageBadge`（"N 条来源"）；详情页原始消息框按"[序号] 群聊/发送人/时间 + 正文"分块，多来源时隐藏单条来源行；复制文本含全部来源。

### 验证
- 新增 4 项测试：合并取更晚/更早不改（含已完成拒绝合并）、管线跨群复用、详情多消息、迁移回填与幂等。
- 构建 0 错误；回归仅剩改前已存在的 `Native WeChat reader matches the frozen Python oracle` 失败（已在干净基线复现，与本功能无关）。
