# 2026-09-26

## 修复：待办详情「查看原始消息」导致程序崩溃
- 定位方式：Windows 事件日志（应用程序日志，.NET Runtime，事件 1026）拿到真实异常堆栈——`System.ArgumentNullException: Value cannot be null. (Parameter 'item')` at `DataGrid.ScrollIntoView`，来自 `Behaviors/DataGridScrollIntoViewBehavior.cs:39`。
  - 这条定位路径非常有效：WPF 未处理异常会写入事件日志，可直接用 PowerShell `Get-WinEvent -FilterHashtable @{LogName='Application'; ProviderName='.NET Runtime'}` + `Id=1026` 取出完整堆栈。
- 根因链：点击「查看原始消息」→ `TodoFeatureCoordinator.NavigateToMessageAsync` 先 `_selectTab(2)` 切到消息流，切页触发 `SidebarNavigation_SelectionChanged` 里的 `MessageFeed.RefreshAsync()`（会 `SelectedMessage = null`），与随后 `ShowContextAsync` 的选中项设置竞争；滚动行为用 `BeginInvoke` 延迟执行，回调时 `SelectedItem` 已被清空 → `ScrollIntoView(null)` 抛异常 → `async void`/调度器未处理 → 进程终止。
- 修复：
  1. `DataGridScrollIntoViewBehavior`：回调内重新读 `grid.SelectedItem` 并校验仍在 `grid.Items` 中，否则跳过。
  2. `MessageFeedViewModel`：新增 `_pendingContextMessageId` + `PrepareContextNavigation()`；`RefreshAsync` 在跳转期间改为重新定位上下文；`LoadPageAsync` 丢弃过期整页结果；`Items.First` → `FirstOrDefault`。
  3. `TodoFeatureCoordinator.NavigateToMessageAsync`：切页前先登记跳转目标。
  4. `App.xaml.cs`：新增 `DispatcherUnhandledException` / `AppDomain.UnhandledException` / `TaskScheduler.UnobservedTaskException` 兜底，写入 `%LocalAppData%\WechatDashboard\logs\crash-yyyyMMdd.log` 并弹提示，不再直接崩进程。
- 验证：临时写了 tools/repro-navigate 复现程序（已删除），确认旧滚动逻辑稳定抛 ArgumentNullException，修复后并发跳转 5/5 保持上下文；tests/Program.cs 新增两条回归测试均通过。
- 注意：测试套件里 "Native WeChat reader matches the frozen Python oracle field by field" 为既有失败（与本次改动无关）。
- 注意：`dotnet build` 默认 Debug；`dotnet run -c Release --no-build` 会用旧二进制，改动后需按配置重新构建再跑。
