## 邮件收取失败排查：@pcitc.com 不在 eYou 服务器上（重要结论）

- 实测：`shaofeng.dai@pcitc.com` 与 `shaofeng.dai` 两种账号格式，在 `amail.sinopec.com:993` 与 `imap.sinopec.com:993` 上均被拒（`NO login failed (password failed:0)`），说明**不是账号格式问题**。
- 服务器归属（关键）：
  - `amail.sinopec.com`=10.249.104.100、`imap.sinopec.com`=10.249.104.98、`webmail.sinopec.com`=10.249.104.96，greeting 为 `eYou MUA v8.18.2 … server starting on sinopec.com`，登录页标题“中国石化邮件系统” → **集团 sinopec.com 邮件系统**；993 开放、143 拒绝。
  - `mail.pcitc.com` / `mail.sinopec.com`=10.53.251.50，`_autodiscover._tcp.pcitc.com` SRV 指向它，OWA 响应头 `X-OWA-Version: 15.2.2562.56`、`X-FEServer: EX-HKMAIL-10` → **Exchange 2019**，承载 @pcitc.com；开放端口仅 25/443，**143/993/110/995/1993 全部 timeout（IMAP4/POP3 未启用或被过滤）**。
- 结论：程序硬编码的 `SinopecMailOptions.Host = amail.sinopec.com` 只服务 @sinopec.com 账号；@pcitc.com 邮箱在 Exchange 上且未开放 IMAP，因此必然登录失败。
- 另核对：本机 DPAPI 密文 `%LOCALAPPDATA%\WechatDashboard\Mail\protected-imap-credential.bin` 解密出的账号正是 `shaofeng.dai@pcitc.com`、密码与用户给的一致（10 字符），可排除“设置时输错”。
- 待用户决定：① 用 OWA 验证密码有效性；② 若有 @sinopec.com 集团邮箱则改用它；③ 申请 IT 开通 Exchange IMAP4；④ 程序增加可配置 host 或改走 EWS（工作量大）。
- 排查未做：未继续试探其它账号格式（`pcitc\shaofeng.dai` 等），避免触发域账号锁定（已消耗约 5 次失败登录）。
- **补充（17:35，关键）**：用户反馈该账号登录需要 **OTP 二次验证**。已用“不存在的账号”做对照实验：`zz_not_exist_9917@sinopec.com` / `@pcitc.com` 在 `amail.sinopec.com:993` 得到的响应与真实账号**完全相同**（`NO login failed (password failed:0)`），说明该服务器在 IMAP 通道对任何账号都返回同一句通用拒绝——即 **开启 OTP 后 IMAP（只有静态密码、无第二因子字段）被一律拒绝**，与账号格式、密码正确性均无关。eYou 登录页 JS 里确实带 OTP/短信验证码分支（错误码 20/21/22/23/24）。
- 因此结论修正为：根因是**邮箱启用二次认证，IMAP 无法承载 OTP**。可行路线：① webmail 里找“客户端专用密码/独立密码/授权码”，用它替代登录密码（eYou 部分部署支持）；② 若无此功能则 IMAP 路线不可行，改用已有的 mbox / JSONL 本地文件采集通道，或让 IT 开白；③ 程序侧的登录失败提示应改为“该邮箱已启用二次验证，需使用客户端专用密码”，避免再误判成密码错误。
- 补充验证：已确认用户截图是 eYou「中国石化邮件系统」登录页（统一身份账户/邮箱账户 + 密码 + OTP，验证方式 OTP/短信/二维码）。另补测 **SASL `AUTHENTICATE LOGIN`**（不只是 `LOGIN` 命令），两种账号仍返回同一句 `AUTHENTICATE failed (password failed:0)`；官方帮助（`/user/?q=help&type=hot&did=31`）只说第三方客户端用 `imap.<域>.com` + “登录邮箱的密码”，未提 OTP/授权码，属通用模板。累计失败约 9 次，已停止盲试。

## 石化邮改回“客户端本地缓存优先”（用户决定，2026-11-04 晚）

- 用户结论：IMAP 走不通就从客户端已收邮件里读。本机已装「石化邮 2.4.0.9」（Thunderbird 内核），缓存就在 `Documents\sinopec\default\profile\ImapMail\amail.sinopec.com\INBOX`（2274 MB），`prefs.js` 里 identity=`shaofeng.dai@pcitc.com`、server1=imap/amail.sinopec.com。
- 代码改动（4 处 + 测试 + 文档）：
  - `CaptureAdapterFactory.CreateDefaultLiveSources` 重新注册 `CreateSinopecMailArchiveSource()`；
  - `ApplyDirectMailPolicy` → **`ApplyMailSourcePolicy(sources, archiveAvailable?, hasImapCredential?)`**：缓存 `IsEnabled = 可用 && 原值`、Location 取真实 INBOX；IMAP `IsEnabled = 原值 && 已存凭据`。两个可选参数专为测试注入，避免依赖本机真实邮箱。
  - `MboxMailArchiveReader` 新增 `ReadTail(maxMessages, maxBytes)`：在尾部窗口内回溯找 `From ` 分隔行，起点 = `separators[count - limit]`（写成 `count-limit-1` 会少算一封，已被新测试抓到）；窗口内无分隔行则回退 offset 0，绝不漏读。
  - `MboxMailCaptureAdapter` 首次运行改为回溯（默认 200 封 / 48 MB），不再锚定 EOF。
  - `MainWindow`：加载/保存/建管线三处统一走新策略；保存不再丢弃缓存行、不再强写 IMAP=true；界面文案改为“石化邮（默认读取客户端本地缓存）”。
  - 升级兼容：库里没有缓存行 + 缓存可用 ⇒ 判定为升级后首次加载，默认关掉 IMAP，避免每轮一条登录失败；保存一次后按用户勾选。
