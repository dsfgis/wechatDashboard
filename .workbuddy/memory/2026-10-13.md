## 桌面日历「当日日程」滚动条改为明暗双主题样式（用户截图标注需求）

需求：用户发来暗黑/浅色两张桌面日历截图，红框标注位置一致，要求「暗黑模式和浅色模式都要考虑」。

定位过程（无 PIL 环境下读截图标注区域）：
- `Add-Type`（PowerShell 加载 System.Drawing）被安全策略拦截；`pip install pillow` 被沙箱中断。
- 改为纯标准库 Python 写 PNG 解析器（zlib + 反滤波），统计红色标注像素，再做连通/列剖面还原矩形轮廓；最后裁剪放大确认。
- 结论：两张图只标注了一处——当日日程列表右侧的纵向滚动条（红框上下边界即滚动条首尾）。六/日表头等其余红/橙色像素是周末配色，卡片左侧红条是项目色，都不是标注。

根因：该 `ListBox` 没有自定义 `ScrollBar` 样式，走 WPF 默认模板：17 DIP 宽、`#F0F0F0` 浅灰轨道、带上下箭头按钮，完全不随 `DesktopCalendarTheme` 切换，于是暗色面板右侧出现亮白色竖带。

改动（4 个文件）：
- `Views/Todos/CalendarControls.xaml`：新增隐式 `ScrollBar` 样式 + `CalendarScrollThumbStyle` + 透明 `RepeatButton` 样式 + 垂直/水平两套 `ControlTemplate`。轨道透明、滑块 6 DIP 圆角胶囊、无箭头；垂直宽 8 DIP、水平高 8 DIP。
- `Services/DesktopCalendarTheme.cs`：新增 `ScrollThumb`/`ScrollThumbHover`/`ScrollThumbPressed` 明暗色值（浅色 `#C2CAD6`／暗色 `#4A5872` 等）。
- `Views/Todos/DesktopCalendarView.xaml`：列表加 `x:Name="SelectedTodosList"` 供测试定位。
- `tests/.../Program.cs`：新增用例 `Desktop calendar list uses a theme-aware scrollbar in both themes`。

踩坑（重要，值得复用）：
1. 自定义 `ScrollBar` 样式若同时写 `Width=8` 与 `Height=8`，垂直滚动条会被压成 8×8，滑块根本不渲染。必须按 `Orientation` 分别设置：默认只给 `Width`，水平触发里改成 `Width=Auto` + `Height=8`。
2. `RenderTargetBitmap.Render(子元素)` 会带上该元素相对父级的偏移，用 8px 宽的位图取滚动条像素必然全空（`anyAlpha=0`）。正确做法：渲染窗口内容根元素，再用 `TransformToAncestor` 算出目标矩形取子区域像素。
3. 浅色主题下轨道透明会露出白色面板，不能用「最大亮度上限」判断，要用最暗像素判断滑块是否可辨。
