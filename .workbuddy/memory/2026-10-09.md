## 2. 修复 git 仓库（重要经验，之前多次会话都卡在这里）

症状：`git status` 报 `bad tree object HEAD`；fsck 列出 10 个缺失对象；index 的 cache-tree 指向丢失的 blob。

修复步骤（按顺序）：
1. 小流量补发缺失对象：把 `refs/heads/main` 临时指向父提交 `5222de46`、删掉 `refs/remotes/origin/main`，让服务端补发目标提交的增量；必须加 `-c fetch.unpackLimit=1`，否则小包走 `unpack-objects` 会因 thin-pack 增量无法解析而失败（`unresolved deltas left after unpacking`）。
2. 剩余对象用 GitHub REST API 重建并**逐字节校验 SHA-1 后**才写入：
   - `/git/commits/{sha}`、`/git/trees/{sha}`、`/git/blobs/{sha}`（base64）。
   - 注意：API 返回的日期是 UTC，还原 commit 时要补回 `+0800`；tree 的 mode `040000` 要写成 `40000`；commit 正文末尾要有换行。
   - 递归处理：补回的 tree 可能暴露更深层缺失，需要多轮 fsck + 修复。
3. index 的坏 cache-tree 用 `git read-tree HEAD` 重建后再 `git add`。

结果：真实分支（main / training / codex 分支 / tag v1.0）对象全部完整。仅剩 4 个对象（blob `0b36aff1`、tree `0e22d16d` / `12dd504f` / `1b0f4b9d`）只被 2 个 `refs/codex/turn-diffs/checkpoints/*` 引用，远端返回 404（从未推送），无法恢复；因此每次 commit/fetch 的自动维护（geometric-repack）都会报错，建议删除那 2 个过期的 codex 检查点引用。
