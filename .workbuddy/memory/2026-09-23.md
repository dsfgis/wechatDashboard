# 2026-09-23

## 修复：自动待办日历归属改按消息发送日期（而非采集日期）

用户反馈：待办放入日历应按微信/石化通消息的发送日期，而不是收集日期。

**根因**：`TodoService.CreateFromMention` 中 `DueAt = TodoDueBucketPolicy.EndOfToday(now)`，`now` 是采集时刻。补采历史消息时（如"读取当天微信消息"补采），待办落在采集当天的日历格。

**修改**：
- `src/WechatDashboard.Application/Todos/TodoService.cs`：`EndOfToday(now)` → `EndOfToday(message.SentAt)`；`now` 仅用于 CreatedAt/UpdatedAt。补采历史消息时待办落在发送日，发送日已过则自动进"已逾期"桶。
- `tests/WechatDashboard.Tests/Program.cs` TestTodoCreationAsync：固定 SentAt，新增补采场景断言（昨天发送 → 昨天末尾到期 → Overdue）。
- `specs/manual-todo-and-groups/design.md`：同步更新 D-014、7.5 场景、验证清单中"自动待办 DueAt"契约。

**测试**：dotnet run 测试套件 75 PASS / 1 FAIL。唯一失败 "Native WeChat reader matches the frozen Python oracle field by field"（压缩消息 content summary）与本次改动无关，是既有失败（改动仅涉及待办到期日，不触及 native reader）。
