- 改动：`OpenAiCompatibleMessageActionModel.ProjectBriefingMaxTokens` 2500 → 4000，注释说明 80 条消息可能撞 `finish_reason=length`；同步更新 `tests/WechatDashboard.Tests/Program.cs` 断言（2500 → 4000）。
- 验证：App 进程占用 bin 无法整体编译，改用 `-p:BaseOutputPath=D:/temp/wd-verify/bin/` 独立输出目录编译并运行测试，113 项 PASS；2 项失败均为输出目录改道导致的相对路径/缺少 python oracle，与改动无关。
- 待办建议（未实施）：给 `ProjectBriefingOutcome` 增加 `FallbackReason` 并在界面显示，避免“模型不可用”继续掩盖真实原因（周报 `WeeklyReportOutcome` 已有该字段可参照）。

## 自动待办规则（Agent 记忆）——新增功能
- 需求：用户要能教 Agent “要 OTP 码这类事不要建待办”，需要入口 + 记忆。
- 契约：`src/WechatDashboard.Application/TodoRules/TodoRule.cs` —— `TodoRule(Id, Text, IsEnabled, CreatedAt)`、`ITodoRuleRepository`、`TodoRuleMatcher`（分隔符 `，,、；;/|`+空白切词，单字忽略，正文与群名都匹配，`Normalize` 校验空/超长/无有效关键词）。
- 持久化：新表 `todo_rules`（`rule_text` COLLATE NOCASE UNIQUE），迁移 v11 `auto-todo-rules-v1`；`SqliteTodoRuleRepository` 支持增/启停/删，重复添加返回既有 id。
- 双重生效：① `MessageCapturePipeline` 在 `needsAgentDecision` 前先跑 `TodoRuleMatcher.Match`，命中则跳过模型且不建待办（消息仍入库、分类、评分）——确定性兜底，不依赖模型；② `OpenAiCompatibleMessageActionModel.BuildMentionSystemPrompt()` 把启用关键词追加到系统提示，覆盖语义相近说法。模型对象通过 `Func<IReadOnlyList<TodoRule>>` 每次读取快照，新增规则无需重启。
- 界面：模型配置页底部“自动待办规则（Agent 记忆）”区块（输入框 + 添加到记忆/启用停用/删除 + DataGrid + 状态行）；整句长文本会提示改填短关键词。手动“转为待办”不受规则限制。
- 测试：新增 `TestTodoRulesAsync`（匹配语义、仓储往返、管线拦截与停用后恢复、提示词注入），全套 114 PASS。
