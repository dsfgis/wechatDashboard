## 详情把「已完成」改回活动状态后要重新出现在待办与日历

- 诊断结论：`UpdateTodoAsync` 写 status / 清 completed_at 正常，`TodoWorkbenchViewModel.RefreshAsync()` 也会把行移回活动分组；**唯一缺陷是日历未刷新**——详情回调只刷工作台，`DesktopCalendarViewModel`（日程概览与桌面日历共用实例）缓存未更新。`MainWindow.RefreshAsync()` 只刷当前 Tab，不能代替全局刷新。
- 修复链路：MainWindow 注入 `refreshCalendar: () => ScheduleOverview.RefreshAsync()` → `TodoFeatureCoordinator.refreshRelatedViews`（MessageFeed + 日历）→ `TodoWorkbenchViewModel.RefreshTodoViewsAsync()`（工作台 + 相关视图）→ `TodoDetailViewModel._refreshWorkbench`。提醒处理改用 `RefreshAllViewsAsync()`，`onTodoCreated` 也补上日历刷新。新增构造参数一律追加末尾且可选。
- 兜底：`TodoDetailWindow.Closed` 调用 `TodoDetailViewModel.SaveStatusIfChangedAsync()`，只提交状态、字段取持久化快照、异常内部捕获；`_hasUnsavedStatusChange` 由 Status setter 维护，保存/完成后清除。`SaveAsync` 改为 public 便于测试驱动。
- 文案：`TodoDetailWindow.xaml` 状态提示改为「改回活动状态并保存后会重新出现在待办理与日历；直接关窗也会保存状态改动」；README 第 20 行原文「不再提供状态下拉」已过时，一并更正。
- 验证：新增 `TestReopenedTodoVisibilityAsync` 与 `TestTodoStatusRefreshWiringAsync`，完整 runner **120 PASS / 0 FAIL**；解决方案构建 0 错误。
